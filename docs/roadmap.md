# Roadmap

Where the blueprint is heading in the next twelve months, until October 2027, and what it will not do. It is a direction, not a promise: the needs of the repositories made from it set the order. Ideas are welcome as [feature requests](https://github.com/Dennis-Otto/repo-blueprint/issues/new?template=feature_request.yml) or in the [discussions](https://github.com/Dennis-Otto/repo-blueprint/discussions).

The [changelog](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md) names every change of every release. Each step leads to the section of its last minor release, and the changelog goes back from there to the first release of the step. The larger steps so far:

- **[0.1 to 0.3](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#030-2026-10-07):** seven kinds of projects, the settings as code, the security checks of the workflows, fuzzing and property tests, the release bot with the changelog that the pull requests write, the verification of every release, prereleases, the dev container, the dashboard and Harden-Runner.
- **[0.4](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#040-2026-10-07):** the settings bot that applies the settings as code itself, OSV-Scanner, area labels, the changelog check and the licenses of the third-party components in every release.
- **[0.5](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#050-2026-10-07):** Renovate instead of Dependabot, a beta channel, the records of decisions, the coverage of every pull request, the flaky-test bot, the SBOM as CycloneDX with an OpenVEX document, the Markdown lint and the announcement of every release.
- **[0.6](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#060-2026-10-08):** a documentation website for every repository, the build of every release in an isolated workflow (SLSA Build Level 3), release tags signed without a key, mutation tests every week, the taint analysis of Psalm for a Nextcloud app, hints at the spelling and the style of the documents, the clean-up bot, the weekly report, the health of every repository on the dashboard and the documents that the Silver level of the OpenSSF Best Practices badge asks for.
- **[0.7](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#070-2026-10-08):** the settings that every website shares, from the blueprint, and a successor that the owner designated on GitHub, who can carry the project on.
- **[0.8](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#080-2026-10-08):** websites in more than one language, issue forms that point to the documentation, and the website of the owner itself made from the blueprint.
- **[0.9 and 0.10](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#0100-2026-10-12):** the Rollout, which brings every release to every repository within minutes, one repository after the other, where the weekly run of the blueprint bots took up to a week ([decision 0052](decisions/0052-roll-out-every-release-at-once.md)), with one update pull request that each release moves on; the branch bot, which brings the pull requests of Renovate up to date with `main` too, so that an update whose checks passed merges without waiting for the next run of Renovate; checks that run only where they can change a result; and checks and releases that stall get going again without a person.
- **[0.11 and 0.12](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#0120-2026-10-14):** the diagrams as pictures that every reader sees, also in the GitHub app and the stores, the PR coach, which explains every check that fails, the bot-health bot, which keeps an issue open while a bot fails, an `AGENTS.md` for the coding agents, the fragments of the changelog in `changelog.d/`, over which pull requests no longer conflict, and release tags that only the release app creates.
- **[0.13](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#0130-2026-10-19):** the blueprint for any owner, with a release app of their own, Renovate of their own and an issue assistant with or without AI, and `blueprint.py create`, which makes a new copy its repository with one command; the screenshot bot, whose pictures change only when their pixels change, in every repository and for the blueprint's own documentation, with pictures of the website and, by its kind, of the integration in Home Assistant or the app in Nextcloud from the first run of a new repository; pull requests that fix what a command can fix by themselves, and one report on each that says what it makes; a page for every question of Copier and every variable, the questions and answers, the troubleshooting, the architecture, the comparison with other templates and a page for each kind of project; a page of the automation and a website that is accessible and quick in every repository; the answers of OpenSSF Best Practices and of the OSPS Baseline, proposed in every repository; and the data of the dashboard as JSON and a feed of the releases.
- **[1.0](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#100-2026-10-19):** the blueprint is stable, and has a policy of versions. A release that asks something of a repository made from the blueprint, such as a required check with a new name, a question of Copier that changed or a file of the project to change by hand, is a new major version, with what to do under *Breaking changes* in its notes; every other release is a minor or a patch version, and only the latest release gets [the security fixes](https://github.com/Dennis-Otto/repo-blueprint/blob/main/SECURITY.md#supported-versions).
- **[1.1 to 1.5](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#150-2026-11-01):** an eighth kind of project, the Chrome extension, whose every release reaches the Chrome Web Store by itself; the settings app, an optional second app that writes the administration, so that the release app can give it up; one list of the repositories that follow the blueprint, `.github/fleet.toml`; jobs with secrets or with tokens that write, which block every host that they don't need; every tool of the checks with its findings at their lines, and no check without its explanation; the dependency updates of a day in one release; assets of the project's own in a release, attested like the rest; a pull request that hears when it changes a file of the blueprint, and where the change belongs instead; one command that registers the release app; a token for its one repository in each run of Renovate; and the branch bot for the pull requests from forks too, with the unsigned commits shown before they block a merge.
- **[1.6 to 1.9](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#190-2026-11-03):** a map for AI assistants, `llms.txt`, on every website; websites with several further languages; pull requests that correct their title and draft their entry of the changelog, lock files of pip-compile and checks of the project's own workflows that fix themselves, and the fixers on `main` every week; the runs of a replaced commit, which give their runner back; the candidates for a good first issue, which the issue assistant names; the accessibility check at the width of a phone; a Nextcloud app that signs in an environment of its own and posts to the App Store from another; and tests of the blueprint that take about a third less time.
- **[1.10 to 1.13](https://github.com/Dennis-Otto/repo-blueprint/blob/main/CHANGELOG.md#1130-2026-11-08):** a ninth kind of project, the Cloudflare Worker, which Cloudflare deploys with each release, with no key of Cloudflare in GitHub; `/fix`, which commits the fixes of the checks that failed, also onto the branch of a fork; the screenshot bot in shards side by side, with files besides pictures, such as the recording of a demo, only the hosts that a project names and a time limit for its script, so that HomeDarts for Autodarts uses the shared workflow; container images at SLSA Build Level 3, from an isolated build like every other asset; the repositories of other owners made with the blueprint on its website; and the badge of the issue assistant in the README of a new repository.
- **OpenSSF Best Practices:** the blueprint holds [the Silver level](https://www.bestpractices.dev/projects/15284) of the badge.

## Next

- **Visual changes in pull requests:** a pull request that changes what a picture of the screenshot bot shows gets that picture before and after the change in its report, rendered by the same script, and one that changes the website gets its changed pages, before and after.
- **Commands in pull requests:** `/update`, `/retest` and `/automerge` in a comment of a pull request, beside `/fix`, which commits the fixes of the checks that failed.
- **More kinds of projects:** actions in JavaScript and TypeScript, cards for the dashboards of Home Assistant, and apps of Home Assistant (add-ons).
- **A website that shows the blueprint:** a logo and colors of its own, and a page that builds the command of `copier copy` from your answers.

## Always

- New versions of the dependencies and the actions, and every new major version of Nextcloud, reach the repositories through the update bots.
- Every new release of the blueprint reaches every repository made from it as a pull request of the blueprint bot: within minutes for the repositories of the release app, which the Rollout takes one after the other, and with the weekly run of the bot for every other one.
- What GitHub adds for the security of repositories and releases is taken up when it fits, as immutable releases and their attestations were.

## Not planned

- **Forges other than GitHub.** The blueprint builds on the rulesets, environments, attestations, immutable releases and the API of GitHub.
- **Releases by hand.** Versions follow the titles of the pull requests, and the notes are the text that they write in their fragments of the changelog or under *Unreleased*.
- **Bots that merge what nobody approved.** Only updates that pass every check merge on their own; every other change waits for a person.
- **Secrets in files.** `blueprint.py` never reads or sets the value of a secret, and no file of the blueprint holds one.
