### Features

- The release pull request is rebuilt once before it merges, not after every merge: a merge of `docs`, `chore`, `ci` or `test`, such as an update to a new release of the blueprint or new pictures, changes nothing that it releases and no longer pushes two new heads to it with every check behind them. A merge that changes its notes, a `feat`, a `fix` or a `perf`, still rebuilds it at once. Once auto-merge is on for it, every run of the release bot rebuilds it, and turning auto-merge on for a release pull request that is behind `main` has the branch bot start the release bot within minutes, rather than update its branch; the daily run and a run by hand rebuild it too. A release of dependency updates still merges by itself, daily and at once with the fix of a vulnerability. A release pull request that is behind `main` when you turn auto-merge on merges one round of checks later, about 15 to 25 minutes.
