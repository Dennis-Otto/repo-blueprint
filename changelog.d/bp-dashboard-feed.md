### Features

- **The dashboard publishes its data as JSON and a feed of every release, and shows the websites:** what the dashboard showed existed only as a page of HTML, so the owner's website could show the version and the numbers of each project only by asking GitHub's API in the browser of every reader, and there was no feed of the releases. Now the Dashboard workflow publishes beside the page `dashboard/repos.json`, with every value of the page for each repository, its description, website and stars, and `null` where nothing is known, and `dashboard/releases.atom`, an Atom feed of the 30 newest releases across all repositories, without prereleases, each with the beginning of its notes; the head of the page names both, so a feed reader finds the feed from the address of the page. These addresses and `dashboard/history.json` stay, and the job that publishes the dashboard asks for each after every deployment. The new column *Website* shows the last run on `main` of the Docs workflow, which builds and publishes the website of each repository.
