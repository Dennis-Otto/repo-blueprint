### Features

- The scans of a pull request no longer start a run of *Findings* and one of *Bot health* behind it: a job of *After the checks* dismisses the alerts of the pull request that `.github/findings.toml` accepts, right after each scan of CodeQL, Workflow security or OSV-Scanner, so that their review threads don't block the merge, as before. A dismissal that fails tries once more in the same run, and when that fails too, the pull request says so once for each commit. `.github/issue-assistant/config.toml` sets `pull_requests = false` under `[findings]`, with which the issue assistant writes `findings.yml` for the scans of `main` alone, and its check expects that form. A new alert on `main` still fails a run of *Findings* and opens its issue. In the repositories of the blueprint that is about 7,200 runs a week less.
