### Bug fixes

- **A release that GitHub made public despite an error reaches every repository:** GitHub answered the call that made v1.11.1 public with an HTTP 502 and made the release public all the same, so the job that publishes failed; the Rollout after the attempt that ran the job again took the release for an older one and brought it to no repository. Now the job reads the release again after a call that failed and passes once the release is public as asked, or makes the call again, three times at most, as it does with the categories of the discussions; and the Rollout takes the release that went public while a job of the run that publishes ran, in whichever attempt of the run ([#661](https://github.com/Dennis-Otto/repo-blueprint/issues/661)).
