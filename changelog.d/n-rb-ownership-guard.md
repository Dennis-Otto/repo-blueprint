### Features

- **A pull request hears when it changes a file of the blueprint, and where the change belongs instead:** the next update of the blueprint that changes the same lines conflicts with such a change and then waits for a person. The check *lint* now annotates each such file, and the report of the PR coach names them, says where the change goes instead, such as `.github/repository.project.toml` or a workflow of its own, links a new issue in the blueprint filled in with the files, and adds the label `blueprint-file`. It is a notice that fails nothing, unless the repository variable `BLUEPRINT_OWNERSHIP` is set to `fail`. The list of these files comes with the update as `.github/blueprint/owned.txt`, so a workflow of a project alone is on no list, and the bots stay out of it.
