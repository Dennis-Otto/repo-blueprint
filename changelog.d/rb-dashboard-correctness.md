### Bug fixes

- **The dashboard and the weekly report show the real state of every repository:** the blueprint's own CI, `ci-python.yml`, is found, so its row shows its CI, coverage and CI time instead of "–", and the weekly report its CI time. The column Verification shows the newer of the weekly run of the release verification and its job in the run of the Release workflow that made the latest release, where GitHub lists it, instead of "–" in every row. A run that GitHub skipped, such as one of Findings that the CodeQL of a pull request started, no longer turns a failed workflow into a ✔, and neither does a pull request from the `main` of a fork. The first answer to an issue counts only the answers of a person, not those of the issue assistant or another bot, and leaves out issues that a bot opened; its column is named "First answer by a person". A history of the published dashboard that can't be read, such as during a hiccup of GitHub Pages, fails the run, so that the website keeps its trends of up to 120 days instead of a history of one day; only a history that isn't there yet starts a new one. Every request to a website gives up after 30 seconds and every download of a report after two minutes, and a report that can't be read, such as a broken zip or XML file, leaves out its own value instead of failing the page. The new columns Mutation and Renovate show the last run of the mutation tests and, in the blueprint, of Renovate; a workflow that a repository doesn't have shows "–" as "not set up". The health table shows "✘ failed" with the run where the last run of its workflow failed and no value is known, and a CI under a minute as "< 1 min" instead of "0 min". A repository whose update of the blueprint is open shows the pull request of the blueprint bot, such as "v0.9.1 → v0.10.1 · #226", in the colour of its checks, instead of looking as if it fell behind. The dashboard is built every two hours instead of every six, and after a change of the changelog, which a page of the website includes. The weekly report counts from the minute of its run a week before, not from the start of that day, so that two reports no longer count the same hours, and takes its numbers from the totals of GitHub's search instead of the items of one page, which stopped at 100.
