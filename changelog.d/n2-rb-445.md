### Features

- **Each run of Renovate holds a token for its one repository:** the Renovate workflow of the blueprint made one token for every repository of the release app, so a package manager that runs code of a dependency while it writes a lock file could push to all the others. It now lists the repositories with a token that only reads and runs Renovate once for each of them, two at a time, with a token for that repository alone. The log shows what the token reaches, and Renovate doesn't start when that is more than its repository; the issue *Renovate logs problems* still lists the problems of every repository. The workflow of a repository that runs Renovate itself keeps its one job and gets the same look at its token, so an existing repository has nothing to do.
