### Bug fixes

- **Every merged fix reaches the next release, whatever its description holds:** release-please skipped a pull request whose squash commit it couldn't parse, title included, such as an update of Renovate that quotes release notes or an advisory with a line like `**[(Full`, and the fix waited for another release, which didn't list it. Before release-please runs, the release bot now writes the title and the lines `Release-As:` and `BREAKING CHANGE:` of each merged pull request since the last release that can change it into the end of its description, as an override in an HTML comment that release-please reads instead of the commit. Decision 0060 says why.
- **The release pull request changes only when its notes change:** release-please rebuilt it in every run, also on the same commit, and every check of it started again, because the header of its description ended with a line end that release-please trims when it reads the description back. The header now ends with an HTML comment.
