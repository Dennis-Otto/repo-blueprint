### Bug fixes

- **A heading on your website has the anchor that GitHub gives it, also with a no-break space, two spaces or an emoji:** French puts a no-break space before `?`, `!`, `:` and `;`, and the website made it a hyphen where GitHub drops it, so a link copied from the website missed the heading on GitHub, and a link written for GitHub failed the strict build. Now `De quoi ai-je besoin ?` with its no-break space has `#de-quoi-ai-je-besoin` on both, not `#de-quoi-ai-je-besoin-`; two spaces, also around inline HTML such as `A <br> B`, make two hyphens, `#a--b`; and an emoji shortcode counts with its name, `Emoji :dart: dart` has `#emoji-dart-dart`, not `#emoji-dart`. The old ids of such headings stop working: a link or a bookmark to one of them opens the top of its page, and the strict build names each link of your pages that still uses one. Every other anchor stays as it was: escapes, entities, inline code, accents and a raw emoji agreed already, an id of your own such as `{#id}` stays, and a repeated heading keeps `_1`, `_2`. The anchors come from a Markdown extension of its own, `.github/github_anchors.py`, which `.github/mkdocs-blueprint.yml` names, so that Zensical loads them as well.
