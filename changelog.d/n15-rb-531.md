### Features

- **A container image reaches SLSA Build Level 3, like every other asset:** the release workflow no longer builds the image in the job that delivers it, but calls `build-image.yml`, an isolated build of its own, once the release is public. It checks that the tag is the one that the release workflow signed, at the commit of the release, builds the image of that tag for `linux/amd64` and `linux/arm64` with its SBOM, pushes it to GHCR and attests its provenance there, so that the provenance names that build and no other job of the release. The release verification, `SECURITY.md` and the README of a container now ask `gh attestation verify oci://…` for `--signer-workflow …/build-image.yml`; the weekly verification still accepts the provenance of the release workflow for an image made before, until the next release. Every repository gets the new workflow, as `release.yml` calls it, and the pages no longer say Level 2 for an image ([decision 0122](https://github.com/Dennis-Otto/repo-blueprint/blob/main/docs/decisions/0122-a-container-image-is-built-in-an-isolated-workflow-of-its-own.md), [#531](https://github.com/Dennis-Otto/repo-blueprint/issues/531)).
