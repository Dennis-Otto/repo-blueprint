### Bug fixes

- **Fragments of the changelog reach the release as the check takes them in:** a heading with one space too many, such as `###  Features`, passed the check *changelog*, but the release gave it a second Features heading of its own, after every other kind of change; it now joins the entries of its kind. A title such as `# Notes` in a fragment, which the release copied into `CHANGELOG.md` and into the release notes, now fails the check, as a heading `## …` does. The check asks GitHub up to three times for the files of a pull request, so a moment in which GitHub fails no longer fails it, also for the pull requests of bots, which need no entry. CONTRIBUTING.md now says to name a fragment after the branch without its type, such as `changelog.d/dark-mode.md` for the branch `feat/dark-mode`, since a name with a slash is no fragment, and the upstream bot of a Nextcloud app says in its description that it writes a fragment. `blueprint.py unreleased`, which no bot uses any more since the upstream bot writes a fragment, is gone.
