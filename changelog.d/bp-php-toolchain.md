### Changes

- **The tools of a Nextcloud app move to PHP 8.3 and PHPUnit 12, while its code stays checked on PHP 8.2, and the tests run in a random order:** PHPUnit 10.5 and 11.5 get no more bug fixes, and PHPUnit 12 needs PHP 8.3, so a new app starts with `config.platform.php` 8.3.16 and PHPUnit 12 in `composer.json`, and its dev container runs PHP 8.3. The CI now sets up the PHP of `config.platform.php` for the tools and, beside it, the oldest PHP of `appinfo/info.xml`; the new step *Oldest PHP* of `scripts/check.sh` parses `appinfo/`, `lib/` and `templates/` with that PHP and checks with `composer check-platform-reqs --no-dev` that the packages that the app ships install on it, so the app keeps running on PHP 8.2. Renovate no longer proposes PHPUnit 13, which needs PHP 8.4 and whose pull requests could never pass, and brings each major version in a pull request of its own. `phpunit.xml` runs the tests in a new random order each time, after the tests that they depend on, and fails a test that prints or that uses what PHPUnit deprecates; PHPUnit names the seed as it starts, and `vendor/bin/phpunit --random-order-seed SEED` repeats the order. An existing app keeps its tools on its PHP until it moves them in its own `composer.json`: set `config.platform.php` to `8.3.16`, run `composer update --lock`, and Renovate brings PHPUnit 11 and 12. Until it does, Renovate already looks for releases for PHP 8.3, so its pull request for PHPUnit 12 fails, because Composer cannot install PHPUnit 12 for PHP 8.2: close it and move the PHP of the tools instead, which brings PHPUnit 12 with it. A test that depends on the order of the tests can fail after the update: make it set up what it needs itself.
