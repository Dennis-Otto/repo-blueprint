### Features

- Only a run of the release bot that published a release starts the bots that follow one: once the run passed, its verification included, its last job starts *Issue lifecycle*, which closes the issues that the release fixes with its link, and *Screenshots*, which renders the pictures of the new version. The push of every other merge and the daily run no longer start the screenshot bot and the bot-health bot behind it, which were about 1,100 runs a week across the repositories that follow the blueprint. A beta starts neither bot, another prerelease no sweep of the issues, and a repository without `scripts/screenshots.sh` no screenshot bot; should GitHub not start one, the morning sweep and the weekly run catch up, and the release stays green. *Issue lifecycle* keeps its own start after every run of *Release* until a release of the issue assistant lets the blueprint leave it out, so a release sweeps the issues twice until then, which does no harm.
