### Features

- **A new alert of zizmor stops the merge, as one of CodeQL does:** the audit of the workflows (*Workflow security*) now runs in every pull request into `main`, the release pull request too, rather than only in those that change a workflow, and the rules of `main` list zizmor in their rule of code scanning. A pull request that adds a weakness to a workflow, such as an expression of the event in a script, shows the alert at its line and merges once it is fixed or accepted in `.github/zizmor.yml`, instead of turning `main` red in the Findings workflow after the merge. Every alert of zizmor counts, whatever its severity, since Findings fails on each one; a project changes that in `.github/repository.project.toml`. The PR coach tells what to do when an advisory published since the last run on `main` shows as an alert of a pull request that changes no workflow (decision 0073).
