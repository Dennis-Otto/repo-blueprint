### Features

- **A Nextcloud app's tests run on the newest PHP and on its oldest:** the new workflow *Newest PHP* runs PHPUnit after every change of `main` and every week, with the locked tools on the newest PHP that setup-php sets up as a final release, and on the oldest PHP of `appinfo/info.xml` with the newest PHPUnit that runs there, such as PHPUnit 11.5 on PHP 8.2. Until now the tests ran only on the PHP of the tools, and the oldest PHP got a syntax check, so a behavior that a newer or an older PHP changes, such as that of `fclose()` in PHP 8.6, passed every check. A failure of the tests keeps one issue open, *The tests fail with the newest or the oldest PHP*, which names each PHP that failed, and the weekly run closes it once they pass. No pull request waits for the workflow, and an app whose oldest PHP is the PHP of its tools skips the second job.
- **A failed download before those tests opens no issue:** setup-php and Composer get a second try after half a minute, and when that fails too, the bot-health bot runs the job once more instead of reporting your code.
