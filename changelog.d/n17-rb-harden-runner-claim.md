### Bug fixes

- **`SECURITY.md` says which jobs Harden-Runner only watches, and fewer of them do:** it said that Harden-Runner blocks every host that a job with a secret, an OIDC token or a token that may write doesn't need, but twelve such jobs only recorded their traffic ([#719](https://github.com/Dennis-Otto/repo-blueprint/issues/719)). CodeQL, zizmor, Scorecard, the taint report of a Nextcloud app and the publication of the website now block every host but the few that their runs reach. The link check, which reaches every host that the documents link to, keeps a token that only reads, and the weekly issue of broken links is the job *links issue* of its own, which reaches only GitHub; the published website is asked by the job *ask the published website*, which holds no token. `SECURITY.md` now names each job that still only records, with its reason: the delivery to PyPI or npm, which no repository makes yet, CodeQL in a repository with Go, Java or Kotlin, or Rust, whose dependencies it may fetch from hosts that no run has shown yet, the build of an image, and Renovate. A new job that holds such a token and only records fails the tests until `SECURITY.md` names it. A host that one of these jobs reaches only in your repository, such as one that a new check of Scorecard asks, fails the job with the blocked call in the summary of Harden-Runner: tell the blueprint, which adds it.
