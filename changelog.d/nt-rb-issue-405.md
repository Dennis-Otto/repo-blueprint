### Bug fixes

- **A Mutation run in which no mutant ran names the test that failed:** when a test fails in the copy of mutmut before any mutant, each part of the workflow *Mutation* failed with only its exit code, and so did the issue of the bot-health bot. Each part now writes an annotation with the first test that failed and its fix, the marker `@pytest.mark.mutation_unsafe`, which the bot-health bot quotes in its issue. The explanation of the check and `CONTRIBUTING.md` of a new repository name a test that runs a copy of the code in a folder of its own as one that needs the marker: outside of `mutants/`, the code with the mutants finds no configuration of mutmut.
