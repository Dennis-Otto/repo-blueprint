### Features

- **More answers of OpenSSF Best Practices:** `.bestpractices.json` proposes eight answers more of the OSPS Baseline and of the gold level, about 100 in all: GOVERNANCE.md says how a new collaborator gets access and that a person is reviewed before escalated permissions, and how a pull request is reviewed; SECURITY.md describes how the project selects, obtains and tracks its dependencies and how it stores, uses and rotates its secrets; CONTRIBUTING.md names the label `good first issue` for small tasks. The guide lists what only you can answer.
- **No binary that nobody can review:** the new step *Binary files* of `scripts/check.sh` fails on a program, a library, compiled code or an archive in Git, whatever the name of its file, and on every other binary file but pictures, videos, sounds, fonts, documents and the inputs of the fuzz tests in `fuzz/`. A repository with such a file removes it from Git and builds it from its sources where it is needed. Every kind of project now ignores the bytecode of Python, also that of the tools in `.github/`, which a repository of Node or PHP could otherwise commit by mistake.
