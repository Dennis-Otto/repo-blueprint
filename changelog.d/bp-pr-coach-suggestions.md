### Features

- **Pull requests fix themselves where a command can:** a check that failed for the format of the code, trailing whitespace or CRLF line endings, a rule of markdownlint or a table that sets columns side by side used to wait for a person to run the command that the PR coach named. Now the job of the check runs the commands that fix it, on the head of the pull request, and after the checks the new fix bot commits what they changed as one commit onto a branch of the repository, also onto a branch of Renovate, so that an update of a formatter stays green and merges itself; the checks run again, and the comment of the PR coach names the files. On a pull request from a fork, which no bot may push to, it suggests the fixes at their lines instead, ten at most and none twice, for **Commit suggestion**. When a check of `main` fails with such fixes, one pull request from `bot/self-heal` brings them and merges itself, and closes once `main` needs none; a failure of the bot keeps one issue open until it passes again. The bot runs no code of a pull request with a token that can write, takes the fixes as data and commits only text files that the commit has already, outside `.git` and the workflows; it commits at most twice in a row, never a third time, and leaves a pull request with the label `no-bot-fixes` alone. `python3 .github/blueprint.py fix run` makes the same fixes on your machine, and `python3 .github/blueprint.py fix text` fixes the text files alone. Every explanation of `.github/checks.toml` now says in `autofix` how its check fixes itself or why no command can, and `python3 .github/blueprint.py coach verify` lists each explanation of your `.github/checks.project.toml` without one: add `autofix = ["your command"]`, or the reason as a sentence, to each. The bot takes the fixes of Lint and of the CI so far; a check in a workflow of your own project names its commands for a person. The bot commits as the release app; without it, the run warns and the PR coach still names each command.
