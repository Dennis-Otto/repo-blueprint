### Performance

- **A pull request waits for fewer runners:** one job, `lint`, runs every linter, the workflows, the licenses, the Markdown, the issue assistant, the sign-off of every commit and the hints at the prose, where six jobs each waited a minute or two for a runner to work for seconds; the check `conventional title` checks the entry in the changelog as well; one job, `codeql`, analyzes every language, each under the category under which code scanning keeps its alerts, without a gate job of its own; and the integrations of Home Assistant run HACS and hassfest in one job, `home-assistant`. Every step of such a job runs also when one before it failed, so the check reports everything at once, and the PR coach explains each check of the job that failed, with its own fix. REUSE runs from its pinned image, without building the image of its action in every run. The required checks change to `lint`, `conventional title`, `codeql` and, for Home Assistant, `home-assistant`, which the settings bot applies after the update merges; the old jobs run for one more release, so that no pull request waits for a check that no longer runs, and the next release removes them. Once it does, a pull request starts seven to nine jobs fewer.
