### Bug fixes

- **OSV-Scanner and Findings pass again for the test tools of Home Assistant:** Home Assistant pins Pillow 12.3.0 and uv 0.12.23 for the tests of every integration, whose advisories no update can fix until it moves on, so OSV-Scanner failed, the code scanning alerts kept Findings red, and Renovate logged an empty commit for them in every run. The blueprint now accepts every advisory of those two versions in `stacks/home-assistant/osv-scanner.toml`, with the reason and until 2026-11-22, and a new Home Assistant integration gets the same `osv-scanner.toml` in its root. An integration that has an `osv-scanner.toml` already keeps it: copy the two entries of `[[PackageOverrides]]` from the blueprint's file into it.
- **Renovate tries no fix of a version that `osv-scanner.toml` accepts:** an entry of `[[PackageOverrides]]` with `vulnerability.ignore` accepts every advisory of one version, such as one that another package pins exactly; `python3 .github/blueprint.py advisories --fix` writes a rule of Renovate for each into `.github/renovate-accepted.json5`, which `.github/renovate-blueprint.json5` extends, and the new step *Accepted advisories* of `scripts/check.sh` fails while the two disagree, or when OSV-Scanner would ignore an `osv-scanner.toml` for a key that it doesn't know. The update brings `.github/renovate-accepted.json5` with the rules of the template; a repository with an `osv-scanner.toml` of its own, such as a Home Assistant integration, runs `python3 .github/blueprint.py advisories --fix` once and commits the file, which the fix bot does in the pull request of the update. Decision 0059 says why.
