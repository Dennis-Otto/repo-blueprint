### Features

- **A new copy becomes its repository with one command, `python3 .github/blueprint.py create`:** the quick start needed a checkout of the blueprint for `blueprint.py`, the owner and the name typed in once more for `gh repo create`, and six commands in the right order, and Copier's message after the copy named a `<blueprint>/blueprint.py` and a `gh repo create --source . --push` that fails in a folder without a commit. `create` comes with every copy: it takes the owner and the name from the answers of Copier, runs `git init --initial-branch=main`, commits the files with a sign-off, creates the repository with `gh repo create` and pushes to it, public unless you add `--private`, applies the settings as code and prints the checklist; `--dry-run` shows the commands first. A folder that pushes to a remote already is refused, and one that `git init` made before is taken as it is, on `main`. The quick start copies with the Copier that the blueprint bot uses, by `uvx` or `pipx run`, and Copier says before its questions what the command after the copy needs, and after the files the command itself.
- **`settings check` names a default branch other than `main`:** a repository whose first branch got the name that Git's configuration gives, such as `master` on Git for Windows, ran none of its workflows, which all run on `main`, and nothing said so. The check now shows the default branch with the place where GitHub renames it and the commands for every clone; `settings apply` leaves the renaming to you.
