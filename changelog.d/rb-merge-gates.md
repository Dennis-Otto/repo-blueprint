### Features

- **A pull request that adds a high alert of CodeQL can't merge, only listed actions run, and secret scanning looks for generic secrets:** the required check `codeql` asserted only that the analysis ran, so a pull request that added a vulnerability merged, and its alert showed only afterwards, when Findings turned `main` red. Any action pinned to a commit could run, and secret scanning saw only the secrets of its partners. Now the ruleset *Protect main* has a rule of code scanning: a new security alert of CodeQL of high or critical severity, or a new error, stops the merge until it is fixed or a maintainer dismisses it with the reason, while an alert that `main` has already stops nothing; `code_scanning_tools` in `[branch]` of `.github/repository.toml` sets the tools and thresholds, and an entry of a tool in `.github/repository.project.toml` replaces that of the blueprint. Only the actions of GitHub and those that `[actions.selected]` lists may run, one pattern for each action that the workflows of the blueprint run, also inside a composite action or a reusable workflow. `python3 .github/blueprint.py settings check` follows every action that your workflows run at the commit of its pin and names each one that the list lacks, with the file that runs it, and until it's listed the settings bot only adds to the allowed actions on GitHub and never removes one, so that no workflow stops: add the patterns of the actions of your own workflows, such as `"owner/action@*"`, to `patterns_allowed` of `[actions.selected]` in `.github/repository.project.toml`. A pull request that adds a new action starts its jobs only once the pattern is on GitHub: run `python3 .github/blueprint.py settings apply` from its branch, as for a renamed required check. Secret scanning now also reports private keys, connection strings and passwords that no provider issued (`secret_scanning_non_provider_patterns` in `[security]`); a switch that GitHub doesn't offer for your repository is named with the line that turns it off, and the other switches still come on. Validity checks have no switch for a repository and stay out of the settings as code ([decision 0038](https://github.com/Dennis-Otto/repo-blueprint/blob/main/docs/decisions/0038-new-alerts-and-unlisted-actions-stop-a-pull-request.md)).
