### Bug fixes

- **A project's own sentences about its releases no longer conflict with every update:** `## Releases` of `CONTRIBUTING.md` now has two marked lines, and every update keeps the text between them, so an existing repository moves its sentences there once. The check *lint* and the report of the PR coach take no notice of a change that stays between them. The sentence that repositories receive the release of an action as a Dependabot pull request now comes with the guide of that kind.
- **The guide says "delivers it to npm" only for a package that goes to npm:** the new answer `publish_to_npm` lets a Node package that no registry takes say so, and `PUBLISH_TO`, `CONTRIBUTING.md`, `SECURITY.md` and the answers of the Best Practices follow from it. An existing repository sets it with `copier update --data publish_to_npm=false`, and can then drop `PUBLISH_TO` from `.github/repository.project.toml`. Its `package.json` and README are its own and stay as they are, so it sets `"private": true` and removes `npm install` from the README by hand.
