### Features

- **The update pull request shows what it brings:** the pull request of the blueprint bot said in one line which release it brings, so an update that skipped releases, from v0.9.1 to v0.10.1 for example, never showed the notes of v0.10.0 in between, and it named neither the files that it changes nor how to resolve a conflict. Its description now shows the notes of every release since the version that the repository has, each in a section to open, the newest first, with references to the issues of the blueprint that still lead there and mentions that notify nobody, a link that compares the two versions, and the files that it changes. With conflicts, it lists the files as a checklist and says how to resolve the markers; otherwise it says whether it merges itself and that the repository variable `BLUEPRINT_AUTOMERGE` set to `off` makes every update wait. Notes too long for the 65,536 characters of a description become links to their releases, and when GitHub doesn't list the releases, the update goes on with a link to them.
