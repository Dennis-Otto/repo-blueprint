### Bug fixes

- **An existing repository gets the label `no-bot-fixes`, and its checklist names the licenses that its dependency review lacks:** release 1.1.0 gave the label that keeps the fix bot away from a pull request only to a new repository, and release 1.3.0 left the license of `wcwidth`, a tool of the blueprint bot, to each project's own `.github/dependency-review.yml`; both were steps by hand that nothing checked, and most repositories never made them, so a contributor could not set the label that `CONTRIBUTING.md` names. The next update adds the label to the group `decision` of `.github/labels.toml` by itself, and the Labels workflow creates it on GitHub; a comment that names the label, such as `# no-bot-fixes: not here`, declines it. `python3 .github/blueprint.py checklist` now names each tool of the blueprint bot that `.github/dependency-review.yml` doesn't allow, with the line to add, which a person adds, since no bot changes the rules of the review where nobody reads the change ([#847](https://github.com/Dennis-Otto/repo-blueprint/issues/847)).
