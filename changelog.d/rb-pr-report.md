### Features

- **One report on every pull request says what it makes:** a pull request showed which of its checks failed, but nowhere which version its merge makes, how its entry of the changelog reads, or how its website looks, and the coverage bot kept a second comment, which on most pull requests only said that no file changes its coverage. The comment of the PR coach is now the one report of a pull request of a person. After the checks that failed, it says what the merge does to the next release, such as *makes the next release 0.13.0, a minor release after 0.12.0*, or that it goes into the release that the release pull request has already, from the title, a `BREAKING CHANGE:` or `Release-As:` line of the description and the release-please files of the default branch, and that a `docs:` or `ci:` change releases nothing by itself. Below that, it shows the entry that the pull request adds to a fragment in `changelog.d/` or to `CHANGELOG.md`, as the release takes it into its notes, or says that the notes list the title. It holds the coverage of the tests against that of `main`, file by file, and the old comment of the coverage bot goes once the report carries the table. The check *docs* now keeps the website that it built for a pull request as the artifact `website` for a week, and the report of a pull request that changes the website links it, with the address of each page that it changes after the merge. A pull request whose checks pass gets the report only when it has something of this to say, so one that changes no coverage, releases nothing and changes no page gets no comment at all, and a pull request of a bot, such as one of Renovate, gets one only for a check that failed, as before. The report reads all of this from the API and the files of the default branch and runs no code of the pull request; the text of its entry and the names of its files appear only as code. The title that the PR coach suggests now also keeps a type without its colon, so *feat add a dark mode* becomes `feat: add a dark mode`. Decision 0029 says why.
