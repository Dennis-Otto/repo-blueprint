### Bug fixes

- **A package that publishes nowhere no longer tells people to verify a package it doesn't have:** a Node or Python package that nobody installs from npm or PyPI, such as a private one, could only set `PUBLISH_TO = "none"` in `.github/repository.project.toml`, which changed the release but not the documents: `SECURITY.md` still said to download a `*.tgz` or `*.whl` that no release has and to run `npm audit signatures`. The new answer `publish_package` decides it: with *no*, the release delivers nowhere, and `SECURITY.md`, `GOVERNANCE.md`, `CONTRIBUTING.md`, the OpenSSF answers, the default topics and the settings speak of no registry. A new repository also gets a `README.md` without `npm install` or `pip install`, and `"private": true` in `package.json` or the classifier `Private :: Do Not Upload` in `pyproject.toml`. An existing repository first takes this release through its update pull request, because the command changes nothing on an older one. On that branch it runs `copier update --defaults --vcs-ref=:current: --data publish_package=false` and removes `PUBLISH_TO` from `.github/repository.project.toml`. Its topics are a stored answer, so with the default ones it adds `--data "topics=typescript, nodejs"`, or `--data topics=python` for a Python package. `README.md`, `package.json` and `pyproject.toml` are its own, so it changes those by hand.
