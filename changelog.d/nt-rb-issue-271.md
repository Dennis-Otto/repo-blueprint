### Features

- **A new repository photographs what it makes from the first run of the screenshot bot:** the `scripts/screenshots.sh` that it starts with renders the social preview and photographs the home page of the website, and by its kind the page of the integration in a Home Assistant in Docker, which runs with `custom_components/` and the integration set up through its config flow, or the app in the apps of the settings of a Nextcloud in Docker, with the app enabled. Each picture comes as `docs/images/screenshots/<name>.png` in the light theme and `<name>.dark.png` in the dark one, taken by the Chromium of the social preview's image with Playwright, which `.github/screenshots-browser-requirements.txt` pins by its hashes and Renovate moves together with the image; the server and the browser share a Docker network without a way out, the clock of the browser stands still, its window is 1280×800 and its letters have gray edges, so the same code renders the same pixels. Add the pictures of your project to the function `shoot()` of the script. The script belongs to the project, so an existing repository takes it over by hand: copy the one of a new repository of its kind, with `.github/screenshots-paths.txt`, from `copier copy` into an empty folder. The job *render* of the screenshot bot now checks out the whole history, so that a picture of the website shows the date of each page as it is published. Decision 0065 says why.
- **The README shows the pages of GitHub that a repository of the blueprint gets:** an update of the blueprint with its checks, the assets of a release with its SBOMs and its provenance, and the comment of the PR coach with the coverage of the tests, each in both themes. `scripts/docs-pictures.sh` photographs them from pages that no longer change, with a clock that stands still long after them, and the Docs pictures workflow renews them when GitHub changes its pages.
