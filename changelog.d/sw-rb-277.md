### Bug fixes

- **The settings bot passes where GitHub keeps a switch of the security off:** GitHub accepts the generic patterns of secret scanning (`secret_scanning_non_provider_patterns`) on a repository of a user and keeps them off, so `settings apply` found the same difference after every run and the Settings workflow failed on `main` of every repository, although it had applied the rulesets and every other setting. A switch of the security that GitHub accepts and keeps as it was, or doesn't offer at all, is now a notice under *GitHub doesn't do this for the repository, which fails nothing*, with the line of `.github/repository.project.toml` that stops asking for it; the bot asks again every time, so that a repository whose plan gains the switch gets it. Every other setting that still differs after its write fails the run as before ([decision 0055](https://github.com/Dennis-Otto/repo-blueprint/blob/main/docs/decisions/0055-what-github-does-not-do-for-a-repository-fails-no-settings-run.md)).
