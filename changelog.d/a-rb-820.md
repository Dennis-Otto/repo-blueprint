### Bug fixes

- **A list that a gateway of GitHub fails to read is read again, and a bot sits out such an outage:** when GitHub's gateway answered a read of a list, such as the rulesets, the labels, the workflows, the runs or the Dependabot alerts, with a page of its own and a 502, 503 or 504, `blueprint.py` gave up at once with "GitHub answered 0", and a bot that sits out an outage of GitHub turned red all the same. It now reads the status that the GitHub CLI names in either form, as `Bad Gateway (HTTP 502)` or as a bare `HTTP 502`: such a read tries again after 10, 20 and 40 seconds, as every other request does, a 5xx that stays counts as an outage, and the error names the status, such as "GitHub answered 502: Bad Gateway" ([#820](https://github.com/Dennis-Otto/repo-blueprint/issues/820)).
