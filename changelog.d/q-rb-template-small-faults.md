### Bug fixes

- **The answer on the direct dependencies for bestpractices.dev names the files that list them:** `external_dependencies` and OSPS-QA-02.01 of a Home Assistant integration and of a GitHub Action no longer say that `pyproject.toml` lists dependencies, which it doesn't there. An integration's answer names the `requirements` of `custom_components/<domain>/manifest.json`, which Home Assistant installs, and `requirements-test.in`, with a link to each; an action's and a Python package's answer name `requirements-fuzz.in` as well, and a package's links its `pyproject.toml`. After the update, the weekly run of Links proposes the new words for the entry. A repository with its own `[external_dependencies]` in `.github/bestpractices.project.toml` keeps it.
- **The checks no longer stop at a traceback on a Python without its standard library:** `scripts/check.sh` and `scripts/diagrams.sh` take a Python 3.12 or newer only when it can import `shutil` and `tomllib`. The dev container of a Nextcloud app has only Debian's `python3-minimal` until its `setup.sh` has installed the rest, so there the steps that need Python now skip with "Python 3.12 or newer with its standard library is not installed here", as they do without a Python, and the hook before a push no longer fails.
