### Features

- **A major update merges by itself once every check passes:** Renovate and the merge bot of Dependabot turned auto-merge on for routine updates alone, so a new major version, such as Psalm 7, waited for the maintainer although every check was green. Every update now merges once every required check passes, a major one too, after the same week of waiting as any other; one whose checks fail stays open with the failure, which is the signal that it needs work. The weekly refresh of the lock files of a package manager that can't keep to versions a week old, such as Composer, still waits for the maintainer (decision 0149, [#838](https://github.com/Dennis-Otto/repo-blueprint/issues/838)).
- **The list of the workflow runs shows the runs that did something:** the end of every check started a run of *Update branches*, and each of those a run of *Bot health*, and nearly all of them skipped, so that almost two thirds of the runs in the Actions tab were runs without a job. The bots after the checks now start the branch bot only when a required check of a pull request failed for good, which moves its line on as before, so a finished check adds neither run any more (decision 0150, [#819](https://github.com/Dennis-Otto/repo-blueprint/issues/819)).
