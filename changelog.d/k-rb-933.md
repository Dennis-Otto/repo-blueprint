### Bug fixes

- **A Home Assistant integration tests with Home Assistant's own test plugin, and with Pillow 13:** the old plugin, pytest-homeassistant-custom-component, is retired, and its last release pins Home Assistant 2026.10 and with it Pillow 12.3.0, whose advisories `osv-scanner.toml` accepted only until 2026-12-20. A new integration now tests with `pytest-homeassistant`, which Home Assistant publishes with each of its releases at the same version, at 2026.11.1 with Pillow 13.0.0, so it accepts no advisory of its test tools, and Renovate brings each new version of the plugin as a pull request of its own. An existing integration keeps its own files of the project, which the update leaves alone; move them by hand, as homedarts-for-autodarts did:
  - in `requirements-test.in`, replace `pytest-homeassistant-custom-component==…` with `pytest-homeassistant==2026.11.1` (`pytest-homeassistant[bluetooth]` for an integration that uses Bluetooth), add `pytest-cov`, `pytest-timeout` and `pytest-github-actions-annotate-failures`, which the old plugin brought, and compile `requirements-test.txt` again with `python3 .github/blueprint.py locks --compile --fix`;
  - in `pyproject.toml`, add `"-p", "no:respx"` to `addopts` under `[tool.pytest.ini_options]`, as the plugin asks: Home Assistant puts its own httpx in place before anything imports httpx;
  - in `tests/`, import the helpers from `pytest_homeassistant.common` instead of `pytest_homeassistant_custom_component.common`; a fixture that only asks for `enable_custom_integrations` can go, since the plugin's `hass` enables the integrations of `custom_components` by itself;
  - in `osv-scanner.toml`, delete the entry of `pillow` 12.3.0, then run `python3 .github/blueprint.py advisories --fix`, which removes its rule from `.github/renovate-accepted.json5`.

  Two things behave differently in the tests: the `hass` of the plugin names a folder `tests/testing_config` as its configuration, without creating it, so a test that writes there, such as a backup or a media file, gets a temporary folder of its own by a fixture `hass_config_dir` that returns `hass_tmp_config_dir`; and its `freezer` moves the clock of the event loop too, so a poll that a coordinator schedules comes due on `freezer.tick`.
