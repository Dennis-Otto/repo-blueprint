### Performance

- **The tests of a Python project run faster on a runner:** on Linux in the CI, `scripts/check.sh` keeps their temporary folders in memory when at least 4 GB are free there and no `TMPDIR` is set. Windows, a job in a container and your own machine stay on the disk. A project whose tests write several gigabytes to temporary folders sets `TMPDIR` in its workflow after the update. Nothing else changes for a repository.
- **The tests of the blueprint take about a third less time:** its own checks run on Python 3.14, on which coverage measures with `sys.monitoring`, the Pythons that its tests start share their bytecode, and the tests read YAML with the parser of libyaml. The check on Windows keeps running the tests on Python 3.12, which the tool of every repository still runs on. `blueprint.py` writes bytecode when `PYTHONPYCACHEPREFIX` names a folder for it, and starts faster from then on; without that variable it leaves none, as before.
