### Changes

- **A newer push to `main` cancels the checks of the push before:** in every repository made from the blueprint, the tests, CodeQL, the link check, OSV-Scanner and the workflow security check that a merge started stop when the next merge lands, as they do in a pull request, so that the runners go to the newest commit and to the pull requests instead of the state of a commit that is already behind. The website, the release and the bots that commit or change GitHub still end what they started, and no push cancels a run on a schedule or by hand. When a late run for an older commit cancelled the run for the head of `main`, the bot for cancelled checks starts it again, so that the coverage of `main`, the alerts of code scanning and the fix bot always see its newest commit (decision 0075).
