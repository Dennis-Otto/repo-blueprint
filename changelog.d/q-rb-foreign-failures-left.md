### Bug fixes

- **Your website is published only with its provenance:** the job *publish the website* of *Docs* signs the website with Sigstore before GitHub Pages publishes it, where it signed it afterwards, so a failure of Sigstore no longer puts out a website that `gh attestation verify` can't check. The signature tries once more half a minute later; when it fails twice, nothing is published, the website stays as it was, and the error *Sigstore failed* says that nothing in your code is wrong.
- **A publication that failed at GitHub Pages or Sigstore heals by itself:** the bot for stopped checks, now *run the checks again that failed outside the code*, runs the failed jobs of such a run of *Docs* on your default branch once more while its commit is the newest, also when the job *docs* failed twice to hand the website to GitHub Pages. When that fails too, the daily look of the bot-health bot starts *Docs* once more instead of opening an issue, and reports only a failure of that run. A broken link or any other failure of *Docs* stays yours, as before.
- **The flaky-test bot ends its report in time while GitHub keeps failing:** its look back over the runs of the 7 days before stops with a warning after a call that GitHub kept failing, and after two minutes, and counts as far as it got, where the report could run out of time and be lost.
- **A gate that only sums up the jobs that it needs gets no row of flaky tests:** the bot reads the file of the workflow and sees such a job by its `needs` and an `if` with `always()` or `!cancelled()`, when a job that it needs failed, so a failure of a shard counts once, also without the words `this job only sums up the jobs that it needs`.
- **Issue assistant sync** says when it couldn't check a release because GitHub or the network failed, so that a run that passed when it ran again gets no row of flaky tests.
