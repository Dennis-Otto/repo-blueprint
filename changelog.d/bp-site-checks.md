### Features

- **The check *docs* checks the website that it built:** lychee checks every link and anchor of the built pages without asking a server, also those that a page writes in HTML, such as `<a href="…">` in a card, those of the theme and those of the 404 page, which the strict build never checked. `blueprint.py site-check site` checks what the hooks of the website promise, with the real plugins: a sitemap in every folder of pages of a website in several languages, which its language switch reads, the 404 page of the default language at the root, one canonical address on every page, the full addresses of its other languages with `x-default`, and each untranslated page in the default language and out of search engines. A new version of Material or of its plugins that breaks a hook now fails the pull request that brings it, and `bash scripts/check.sh` runs the same check after it builds the website. A project adds checks of its own in `scripts/check-site.sh`, which gets the folder of the website and which the blueprint never writes.
- **Every deployment of the website is signed and checked:** the job that publishes the website signs the build provenance of what GitHub Pages publishes with Sigstore, which `gh attestation verify` checks as `SECURITY.md` shows, and then asks the published website for the home page of each language and for an address that leads nowhere, which must answer with 404, so that a deployment that GitHub Pages doesn't serve fails its run.
- **The Links workflow checks anchors and pages of HTML:** a link to an anchor needs the anchor, also in the README of another repository, such as the button that leads to `repo-blueprint#start-a-repository`, and the weekly run checks the pages of HTML in `docs/` too, such as one that leads to another address. The anchors of the Markdown files of the repository, which `--8<--` may put together from others, and the links to pages that only the build writes stay with the check *docs*, which checks them on the built website.
