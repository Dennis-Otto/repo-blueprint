### Features

- **Every website shows how its repository looks after itself:** a new page *Automation*, which the website writes from `.github/workflows/` at every build, lists every workflow with the comment at its top, what starts it, each schedule in words, such as *every Tuesday at 04:40 UTC*, the checks that a pull request needs and the environments and secrets that each workflow uses, grouped into checks, releases, bots, security and maintenance, with the diagrams of how a repository looks after itself and of the way to a release, in English and, on a website in German, in German too. It comes into the menu after the security design with the next update; a `docs/automation.md` of your own takes its place, and a hand-written page about the releases of the blueprint, such as `docs/releases.md`, can go.
