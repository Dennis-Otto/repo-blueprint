### Performance

- **The mutation tests collect mutmut's stats once, not in every part:** mutmut first runs the whole suite with trampolines that record which tests reach each function, which takes about ten times as long as the tests, and each part of the Mutation workflow did that on its own: in issue-assistant, six parts spent 13 to 21 minutes each. Now the job *mutation stats* runs them once and hands `mutants/mutmut-stats.json` to every part, which loads it and runs only its mutants, with the same configuration of mutmut (decision 0083). When a test fails without any mutant, no part starts: the run costs one job, and its summary and annotation name the test, also when pytest prints only a traceback. A pull request that changes how the mutants run collects the stats and tries a sample of about 200 mutants in one part, the same functions each time, for at most 12 minutes, in place of every part.
