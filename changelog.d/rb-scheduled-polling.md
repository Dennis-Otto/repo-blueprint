### Performance

- **Dependabot's updates wake the bots at once, and the bots poll far less:** a merge that auto-merge does with the token of a workflow starts no workflow, so after a merge of Dependabot's updates of the dev container the release bot and the branch bot waited for their schedules, which GitHub runs as it can, often hours late. Dependabot's updates now turn auto-merge on as the release app, as Renovate's do, so their merge starts both bots at once; a repository without the app turns it on with the job's token, as before. With every merge into `main` a push of the release app or of a person, the schedules are only a safety net: the release bot looks once a day instead of every hour, and the branch bot every six hours instead of every half hour, and the bot-health bot still starts a workflow whose schedule GitHub missed. The schedules of a project start about ten runs a day instead of about 78, and with the runs of the bot-health bot and of Issue lifecycle that they start about 20 instead of close to 200, which matters most for a private repository and its 2,000 free minutes a month. No schedule starts on the full hour any more, no comment of a workflow promises a time, and the README has a new section, *What the bots cost*, with every schedule. Decision 0033 says why.
