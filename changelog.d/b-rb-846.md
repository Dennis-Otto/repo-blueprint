### Bug fixes

- **The settings bot leaves the rulesets of an organization alone:** it listed the rulesets of a repository with those of the organization above it, which GitHub names too unless asked without them, so an organization's ruleset named like one that the settings keep, *Protect main*, *Release tags* or *Release tag creation*, was compared, written and deleted as the repository's own, and GitHub refused, which turned `settings apply` red. It now lists only the repository's own rulesets, as it already does with the Actions policies ([#860](https://github.com/Dennis-Otto/repo-blueprint/issues/860)).
- **The verification of a release checks the name inside its tag:** *Verify release* checked that the release workflow signed the tag, but not that the tag is the one of that version, so a new tag at the signed tag of an older release passed. It now compares the name inside the tag, which the signature covers, with the tag of the release, as the release workflow and `SECURITY.md` do, and fails with "The tag v1.2.3 is the signed tag v1.2.2 of another version." ([#846](https://github.com/Dennis-Otto/repo-blueprint/issues/846)).
- **The website of the blueprint shows its own logo** in the header and as the icon of the tab, in place of the book of the theme, and the German pages write "Repositorys" throughout. The page for your own account says that the update pull request merges itself once every check passes, and that `BLUEPRINT_AUTOMERGE` set to `off` makes it wait ([#846](https://github.com/Dennis-Otto/repo-blueprint/issues/846), [#860](https://github.com/Dennis-Otto/repo-blueprint/issues/860)).
