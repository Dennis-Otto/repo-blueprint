### Bug fixes

- **An update of Renovate that makes an npm override needless removes it:** once an update of npm asks for the fixed version of a package itself, such as an ESLint that asks for minimatch 11, the override in `overrides` of your `package.json` used to stay, and a test of the project that wants it gone kept the pull request red until a person removed it. Renovate now runs `python3 .github/blueprint.py npm-overrides --fix` after every update of npm. It takes out each override of every `package.json` with a `package-lock.json` beside it, in any folder, lets npm write the lock file anew with `--package-lock-only --ignore-scripts`, so that no code of a package runs, and keeps the removal only when npm takes no version below the override and none that the lock file didn't have; otherwise both files stay byte for byte. The pull request then turns green and merges by itself. A note `//` beside `overrides` that may speak of the override is named in Renovate's log and stays as it is. On your machine, `python3 .github/blueprint.py npm-overrides` names the overrides that npm no longer needs. The Renovate of the blueprint allows the command at once, and so does the Renovate workflow of a repository that runs Renovate itself; the Mend Renovate app runs no command of the blueprint, so there an override still leaves by hand.
