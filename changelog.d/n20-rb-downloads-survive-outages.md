### Bug fixes

- **A check no longer fails when GitHub's downloads time out for a while:** on 8 November 2026, GitHub's downloads without a token timed out for hours, and the link check of the website, the Links workflow and CodeQL failed in every repository. Every tool that the blueprint's own steps download from a release on GitHub, lychee, CodeQL, gitsign, krankerl, Infection and syft, now comes through GitHub's API with the token of the job, which kept working, tries again after an error of GitHub for two and a half minutes or after a download that stalls for five minutes, and is checked by its sha256; when GitHub keeps failing, the annotation says that it is an outage of GitHub and not a problem of your change. lychee comes from `.github/lychee.sh` instead of its action, with the same rules, cache and report, and CodeQL analyzes with the version that its action brings, which the runner usually has already ([#713](https://github.com/Dennis-Otto/repo-blueprint/issues/713)). The flaky-test bot asks GitHub again when it answers with an error of its own, and leaves a run alone that runs again already. Actions of others that download a tool of their own, such as Harden-Runner, gitleaks and the SBOM action, still download it without a token. A change of lychee in `.github/lychee.sh`, such as its update by Renovate, checks the links of every document. `lycheeverse/lychee-action` leaves the allowed actions: a workflow of your own that still uses it runs `bash .github/lychee.sh` instead, or allows the action in `.github/repository.project.toml`.
