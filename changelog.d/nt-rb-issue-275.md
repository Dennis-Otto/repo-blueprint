### Features

- **A pull request fails while it runs an action that the list of the allowed actions lacks, also one that an action runs in turn:** GitHub starts a workflow only when `[actions.selected]` allows every action that it runs, so an update of a composite action or a reusable workflow, such as one by Renovate, that started to run a new action passed every check and then stopped the workflows after the merge, and in the blueprint every repository after the release. The new step *Check that the allowed actions let every action start* of the check *lint* follows each action at the commit of its pin, with the read-only token of the pull request, and names each one that the list lacks with the pattern to add, at the line of the workflow that runs it; `python3 .github/blueprint.py settings actions` does the same on your machine. `settings check` reads the files of the actions the same way, with one query of GraphQL for up to 50 of them instead of a request for each. Decision 0074 says why.
