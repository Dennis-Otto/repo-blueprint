### Bug fixes

- **`blueprint.py create` on Windows commits the hook and the scripts as executable:** Windows has no executable bit, so Copier couldn't give one to `.githooks/pre-push`, `scripts/check.sh` and the other scripts of a new copy there, and the first commit recorded them as plain files. Git then skipped the hook, and the first pull request failed the check in its step *Git hooks*. `create` now records every file that the template marks executable as such before the first commit, on every platform, and `create --dry-run` shows the step: `git update-index --chmod=+x -- …` ([#710](https://github.com/Dennis-Otto/repo-blueprint/issues/710)). A repository that `create` made on Windows before keeps its plain files: `git update-index --chmod=+x` with the names of its scripts and a commit make them executable, as [the troubleshooting](https://dennis-otto.github.io/repo-blueprint/troubleshooting.html#a-script-or-the-hook-is-not-executable) shows.
