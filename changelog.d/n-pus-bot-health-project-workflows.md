### Bug fixes

- **A workflow of the project that keeps an issue of its own gets no second one from the bot-health bot:** the nightly look reported the latest run of every workflow, so a weekly canary of end-to-end tests that failed against the coming release, which keeps issues of its own, opened *Docker E2E fails on main* as well, the next push that skipped the tests closed it, and the next week opened it again. A workflow now says in a comment line `# bot-health: own-issue` that it reports its own failures, as Diagrams, Newest Node, Newest Python and the Next runner of the blueprint do: the bot opens and closes none of its issues for it, closes the one that it opened before the line came, and still starts it when GitHub misses its schedule.
- **A push no longer hides a missed schedule:** the nightly look counted any run since the time of a schedule as its run, so when GitHub dropped the weekly run of a workflow that pushes start too, the next push made it look done, and what only the schedule does, such as the tests of the coming release, didn't run. Now only a run of its schedule or one started by hand counts, and where a full page of pushes came since, the bot asks GitHub for the latest of each.
