### Bug fixes

- **A workflow of the project that keeps an issue of its own gets no second one from the bot-health bot:** the nightly look reported the latest run of every workflow, so a weekly canary of end-to-end tests that failed against the coming release, which keeps issues of its own, opened *Docker E2E fails on main* as well, the next push that skipped the tests closed it, and the next week opened it again. A workflow now says with a comment line `# bot-health: own-issue` that it reports its own failures on the default branch, those of a push included, as the blueprint's Diagrams, Newest Node, Newest Python and Next runner already did by name. The bot opens and closes none of its issues for it, and closes the one that it opened before the line came. The nightly look now also starts such a workflow, those four included, when GitHub missed its schedule, and lists it in its summary.
- **A push no longer hides a missed schedule:** the nightly look counted any run since the time of a schedule as its run, so when GitHub dropped the weekly run of a workflow that pushes start too, the next push made it look done, and what only the schedule does, such as the tests of the coming release, didn't run. Now only a run of its schedule or one started by hand counts, and where a full page of pushes came since, the bot asks GitHub for the latest of each.
